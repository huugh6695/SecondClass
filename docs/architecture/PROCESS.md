# 协作方式（本项目）

> 这里放**做事的规矩**：请求文件怎么维护、破坏性动作怎么收尾、改已交付的东西要做什么。
> 工程约定见 `CONVENTIONS.md`，业务规则见 `MODULES.md`，环境与部署见 `ENVIRONMENT.md`。
> **本文不依赖仓库外的任何文件** —— 项目规矩的答案都在仓库里。

## 〇、跟用户怎么配合

这几条是用户明确要求、在本项目里一直照做的，**不是建议，是规矩**：

- **一步一指导**：一次只推进一步，用户执行、反馈之后再进下一步。不要一口气甩一堆代码或一次做完多个阶段。
- **用户是 Java / Spring Boot 初学者**：每一步都要讲清逻辑，优先大白话，别堆术语。
- **不擅自改需求、不越阶段**：规则不清楚先问；进入新阶段或新功能前，用选择题让用户拍关键决定（给推荐项 + 讲清取舍）。
- **用简体中文**；阶段收尾给结构化表格汇报。
- 用户说「继续」时，不要重复问他已经确认过的事。

## 一、`requests.http` 两条铁律
- 🔴 **铁律①**：**禁用 `<单号>` 之类占位符**；**不留"必须先跑 A 才能跑 B"的隐藏变量依赖**（未赋值的变量会让请求根本没发出去，IDEA 只报"未替换的变量"）。
  写死示例值 + 注释说明。每组开头自带一条登录块（`client.global.set("token", ...)`），别指望用户先跑别处的登录。
- 🔴 **铁律②**：**新写完一组请求必须"当数据回放"验一遍** —— 验那几行字面文本，不是"我心里觉得对"。
  - **文本三查**：请求行格式 / 头行里混了中文标点（IDEA 会把它拆成两条）/ 用了没赋值的变量
  - **逐条真发**，期望值从注释读（`→ 400` 断 `body.code`；`→ HTTP 401` 断 HTTP 状态；无箭头默认 `200 + code=0`）
  - 兜底断言**无 5xx**
  - ⚠️ 带 `> {% ... %}` 响应处理器的块会**真落数据**；**写操作组结束前抹平状态**
  > 📌 原来有个自动回放脚本 `replay.py`，2026-10-28 跟着 `mvn clean` 一起丢了（和 `doc.txt`、验收脚本同一场事故）。
  > **现在按上面三条手工回放。** 要重建的话，两个已知坑：切块只认 `###` 分组，
  > 行首 `>`（响应处理器）/ `<`（文件体）一律当块结束；`{{$timestamp}}` / `{{$uuid}}` 这类动态变量
  > 必须**每次求值**，否则 requestId 固定，第二次回放会被幂等挡住。

## 二、成对破坏性动作（禁用 / 恢复）
🔴 **只写注释不够**：用户手点过 V7 没点 V8，学生被禁了一整天。
⇒ 要么别把破坏性步骤放进"随手可点"的手工清单，要么**让自动脚本兜住**。

## 三、组字母登记（加新组前先看这条）
`requests.http` 里 A = 回复/追问的敏感词检测（2026-10-11）、B = 登出黑名单（⑧④）、C = 敏感词缓存（⑧⑤）、**D = 提交时「疑似重复」提示（2026-10-14，D0~D8）**、E = 幂等（⑧③）、F~Z 已占用。**已无空闲字母。**
- 🔴 **D 组的近义测试对必须「换虚词、不换实词」**：算法比的是字面共享的实词数。`连续三天`↔`连着三天`、`扣款了`↔`把钱扣了` 稳过（交集 7 / 比例 78%）；而 `热水机`↔`热水器` 交集是 **0**（jieba 切成 `热水+机坏` vs `热水器`）。**别按"我觉得像"写断言**。
