# 批量建账号：怎么把学生/干事名单导进数据库

## 为什么需要这个工具

这个系统**没有注册功能，管理员界面上也不能建号**——51 个接口里没有"新增用户"。
账号是**预置**的，这也是设计文档的模型：`AuthService` 里的 `needChangePassword` 就是按
「**初始密码 = 学号后 6 位**」设计的，管理员的「重置密码」用的也是这条规则。

但 `t_user.password` 存的是 **bcrypt 加盐哈希**，不是明文。bcrypt 每个密码算出来的哈希都
**不一样**（盐是随机的），而且 **SQL 里算不了 bcrypt**。
所以名单必须用代码转成 INSERT 语句——这就是 `GenImportSql.java` 干的事。

---

## 三步走

### 第 1 步 · 准备名单

新建一个 UTF-8 的 `.txt`/`.csv`，一行一个账号（格式见 `users-example.csv`）：

```
学号,姓名,角色[,初始密码]

2023001001,张三,学生
2023001002,李四,学生
2023002001,王五,干事
```

- **角色**可以写中文（`学生` / `干事` / `管理员`），也可以写英文（`STUDENT` / `STAFF` / `ADMIN`）
- **第 4 列不填** → 初始密码自动取**学号后 6 位**
  （`2023001001` → `001001`）。想给某个人单独设密码就填上第 4 列
- `#` 开头的行是注释，空行会被忽略
- ⚠️ **用 Excel 存 CSV 的话**，记得选「CSV UTF-8」而不是普通「CSV」——
  普通 CSV 在中文 Windows 上是 GBK，姓名会乱码
  （工具已经会忽略 Excel 加在开头的 BOM 了，但编码本身还是得是 UTF-8）

### 第 2 步 · 生成 SQL

双击 `gen-import-sql.bat`，或者命令行：

```
gen-import-sql.bat 你的名单.csv
```

它会在本目录生成 `import-users.sql`，并在屏幕上打印每个账号的**初始密码**，自己存好。

> 为什么结果不直接打到屏幕上、而是写进文件？
> 因为 Windows 控制台是 GBK 编码。如果走屏幕重定向，SQL 文件会变成 GBK，
> 灌库时中文姓名就成乱码了。工具**显式用 UTF-8 写文件**，绕开这个坑。

### 第 3 步 · 灌进数据库

```
mysql -uroot -p --default-character-set=utf8mb4 second_classroom < import-users.sql
```

`--default-character-set=utf8mb4` **不能省**，否则中文姓名会乱码。

灌完自查：

```sql
SELECT user_id, user_name, user_type, status FROM t_user ORDER BY user_id;
```

## 几个坑（都踩过）

| 坑 | 后果 | 怎么办 |
|---|---|---|
| 名单里写了 `2023003001` | 和 `seed.sql` 建的管理员**主键冲突**，整个导入报错 | 别在名单里写 `2023003001`，要加管理员就换个学号 |
| 名单里有重复学号 | 同上 | 生成前先自己排一下重 |
| 姓名里带逗号 | 会被当成列分隔符，解析错 | 姓名里别用逗号 |
| 用 Excel 存成普通 CSV | 姓名乱码 | 存成「CSV UTF-8」 |
| 把生成的 SQL 反复执行 | 主键冲突报错 | **这是故意的**——免得把你后来改过的密码又悄悄改回初始值。确实要重置某个人，用管理员的「重置密码」 |
| 学生忘了密码 | — | 管理员重置 → 回到**学号后 6 位** |

## 想手动改一个密码？

不用重跑名单，直接登录后调：

```
PUT /api/auth/password
{"oldPassword":"001001","newPassword":"Abc12345"}
```

新密码要求 **6-20 位，且同时含字母和数字**（`AuthService.changePassword` 的校验）。
